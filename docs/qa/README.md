# Verification

Use synthetic fixtures only. Every native self-test and snapshot flag (`--typing-test`, `--paste-test`, `--grammar-typing-test`, `--integration-test`, `--ui-test`, `--docs-test`, `--web-composer-test`, `--editor-typing-test`, `--own-editor-test`, `--click-test`, `--snapshot`), and `swift test` itself, runs on a throwaway settings suite, `app.parzr.desktop.selftest`, which is wiped at start and exit and never writes `known-words.json`, so a test that applies a fix and undoes it cannot teach your real Parzr a name.

**Parzr's own windows are checked headless, in `swift test`.** The Studio writing space (typing without marks vanishing, Checking showing or buttons disabling), the Option+Space path inside it (card, Return applies, Undo, marks refresh), clicks on marks (middle, underline, left edge, outside every word, after a fix), the Studio and menu-bar-popover controls (Sample, Apply all, Undo, Copy, Settings, Done, Clear session, the menu Settings action, reopening) and the Dock-policy decision (an open window makes the app regular with Show in Dock off, closing the last one returns it to menu-bar-only) are `CardClickWindowTests`, `EditorTypingWindowTests`, `OwnEditorWindowTests` and `UIControlsWindowTests`. They build every window but never order one on screen, deliver events to the views in process (never through the window server or HID), activate nothing, keep a private pasteboard and fail if any window became visible. They need the engine (`PARZR_ENGINE_PATH`, as for the other Swift tests) and skip without it. The `--ui-test`, `--editor-typing-test`, `--own-editor-test` and `--click-test` flags stay for a VM or a spare Mac, because they open real windows and take focus, so they are no longer part of the local release routine; run them only for what a real screen adds: menu-bar ownership, the real activation policy, a minimized window returning, the card as the key window, and Accessibility reading and writing the editor. Public screenshots in screenshots/ depict the current product. Generated JSON reports, local paths, integration fixtures and packaged artifacts belong in ignored dist/qa or dist/native-qa.

The Rust suites check rules, valid contexts, grammar in every mode, composed edit plans, protected spans and Unicode. Swift tests check the native bridge, attributed edits, the playground viewport, draft invalidation during debounce, and correction acceptance with native Undo. The app’s `--health-check` exercises the bundled engine without opening a window or reading editor text; it also reports whether Accessibility is granted and suggestions are paused. Node tests check editor/native-host and LSP protocols. Playwright checks Chromium DOM behavior against the compiled engine through a test messaging bridge.

The explicit native command in README opens an authored RTF in the fixture editor (below) and checks real Accessibility selection, passive paragraph capture, an automatic highlight following an actual typing event, clicking the flagged word, applying through the 340 × 218 point correction surface, bold/italic retention, paragraphs and Undo. Run it only in an interactive macOS session with Accessibility enabled. It checks secure input and verifies its fixture before editing.

The native Sample, Apply all, Copy, Settings, Done and Clear session controls, window Undo, the menu Settings action, the menu-bar popover buttons and reopening a closed window are exercised headless by `UIControlsWindowTests` (authored text, a private pasteboard). `dist/Parzr.app/Contents/MacOS/parzr --ui-test dist/qa/ui-controls` runs the same on a real screen, and additionally checks the menu bar owner and a minimized window returning; it is not part of the local release routine. Swift tests also exercise menu pause/highlight actions, compact navigation and Ignore, insertion anchors beside emoji, and screen-edge placement. This verifies the tested controls; host coverage still needs editor-specific evidence.

See [integrations](../integrations.md) for the distinction between implemented routes and host-specific evidence, and [grammar coverage](../grammar-coverage.md) for linguistic limits. Installed extension messaging, custom editors and signed distribution need separate acceptance checks.

`parzr --typing-test dist/qa/typing` checks an incomplete sentence without final punctuation. It sends a real typing event to an authored plain-text fixture, requires three automatic marks, applies one through the compact popover, checks that the typing caret is preserved and remaining marks return, and verifies native Undo. Contextual spelling tests preserve valid musical `si`, noun `bod`, proper names and personal dictionary entries.

`parzr --grammar-typing-test dist/qa/grammar-typing` types into two authored fixtures, one fixture editor each: a supposed/done sentence and a paragraph with tense, agreement and negative-concord errors. It requires marks for every returned edit, clicks a real underline and correction button, checks that remaining marks return with the typing caret preserved, applies the complete plan, preserves a bold anchor and verifies real editor Undo. Reports and popup screenshots remain in ignored `dist/qa`.

`--paste-test dist/qa/paste` sends an actual Cmd+V to an authored fixture (it reads the fixture's own private pasteboard, never your clipboard), checks the trailing-newline context, requires automatic marks and lowercase `done`, clicks the word itself (delivered to Parzr's own mark overlay window, so the overlay's hit test runs on the click's location), captures the themed correction card and applies both errors with Fix sentence. Native input events supplement AX value notifications; no event characters are stored.

`--web-composer-test DIR PID ID...` checks the rich-text composers of Chromium hosts, which give no word geometry on the composer itself (see [integrations](../integrations.md#firefox-chromium-and-electron)). Start a Chromium host you do not otherwise use on `tests/fixtures/web-composers.html`: Chrome for Testing from Playwright's cache with a throwaway `--user-data-dir`, or a bare Electron app that loads the file. Chromium reports focus only for the frontmost app, so bring that window to the front, then run `PARZR_ENGINE_PATH=engine/target/release/libparzr_engine.dylib mac/.build/debug/parzr --web-composer-test dist/qa/web PID plain slack teams discord notion gmail whatsapp outlook rich mention paragraphs linebreak long`. Each composer is focused through Accessibility, captured as an automatic check, run through the typing engine and marked; it fails unless every edit gets a mark. Nothing is typed or applied.

### The fixture editor

`--integration-test`, `--typing-test`, `--grammar-typing-test` and `--paste-test` never use TextEdit or any app you use. Each starts `ParzrFixture` (`mac/Sources/ParzrFixture`, a small AppKit NSTextView editor, rich or plain text) as a separate process, so Parzr still reads it through macOS Accessibility like any editor. The fixture is an accessory app (no Dock icon) with one non-activating window placed to the right of every screen, so nothing appears on a display, the frontmost app and keyboard focus never change, and it exits by itself when the test process ends, even if that process is killed. Keystrokes and Cmd+V go to the fixture's process only (`CGEvent.postToPid`); nothing is posted to the system-wide HID or session event tap, and the word click is delivered in-process to Parzr's overlay window. Parzr's own marks and card are placed on the fixture's off-screen stage, and a test-only seam (`SelfTestTarget`, which refuses to switch on outside a self test) points the observer at the fixture instead of the frontmost app. These four tests also suppress the Studio window Parzr normally opens at launch. The tests log the fixture window frame and stop with an error if the fixture or the test ever shows a window on a screen or becomes the frontmost app.

Run them from a build folder, where `ParzrFixture` sits beside `parzr` (`swift build --package-path mac` builds both): `PARZR_ENGINE_PATH=engine/target/release/libparzr_engine.dylib mac/.build/debug/parzr --typing-test dist/qa/typing`. The packaged app does not carry the fixture; to drive a packaged build, set `PARZR_FIXTURE_PATH` to a built `ParzrFixture`. They still need Accessibility for the process that starts them. The fixture is checked out of the bundle by `scripts/audit-bundle.py`.

The UI check also exercises the new menu panel’s Settings, About and Open editor buttons. Run `scripts/render-model-report.py RESULTS_DIRECTORY` on a completed model benchmark to create a searchable offline report with every input, expected correction, actual correction and timing.
