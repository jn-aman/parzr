# Keystroke typo fuzz sets

Generated by `scripts/generate-typo-fuzz.py`: every eligible word of every correct base sentence gets one perturbation of each keystroke type, so the sets cover fast-typing slips systematically instead of by example.

| Type | Example |
|---|---|
| drop | this → thi |
| add (adjacent key) | this → thius |
| substitute (adjacent key) | this → thus |
| transpose | this → htis |
| double | this → thiis |
| undouble | will → wil |
| space_in | not → no t |
| space_del | is not → isnot |
| case_start | This is → this is |
| apostrophe_missing | don't → dont |
| apostrophe_extra | books → book's |

Names, numbers, code, URLs, addresses, handles, all-caps words and one-letter words are skipped. Each item records the type (`category`), the word's frequency bucket (`subcategory`: top-100, top-1k, top-10k, rare), whether the damaged token is a non-word or another real word (`word_class`), its position in the sentence and the reference. The base sentences are the clean set, for false alarms.

- `dev.jsonl` / `dev-clean.jsonl`: from the held-out set's dev sentences and `src/dev-extra.txt`. Fixes were made looking at these.
- `test.jsonl` / `test-clean.jsonl`: 10,765 items from the 200 sentences in `src/test-sentences.txt`, written after the fixes and never tuned on. CI's verify job scores this set and fails below the gate in `.github/workflows/ci-release.yml`.

Score with the held-out runner (see `benchmarks/README.md` for the app-path harness and environment):

```sh
python3 scripts/run-heldout-benchmark.py --engine dist/qa/heldout-native --corpus benchmarks/typo-fuzz/dev.jsonl \
  --clean benchmarks/typo-fuzz/dev-clean.jsonl --split all --layers rules,gec --output dist/qa/typo-fuzz-dev
python3 scripts/typo-fuzz-report.py benchmarks/typo-fuzz/dev.jsonl dist/qa/typo-fuzz-dev   # type x frequency matrix
```

The test set is sealed like the held-out test split: the runner scores `test.jsonl` only on CI or with `PARZR_RELEASE_GATE=1`, and then writes totals and per-type, per-bucket counts (`summary.json`, `summary.md`) but no per-item results, so the report script works on dev runs only. CI also compares the test totals with `benchmarks/baselines.json` and uploads the summary (artifact `quality-summaries-SHA`).

Real-word results (a slip that lands on another word, "this" → "thus") are much harder than non-words and are reported separately by the report script.
